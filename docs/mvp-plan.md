# Network Mode Guard v0.1 实施方案

## 1. 要解决的问题

同一台 Mac 同时配置 Clash Verge、Surge、Palantir 等网络工具时，用户需要的不是进入每个客户端管理节点、订阅或规则，而是可靠地在**已配置的网络模式之间切换**。常见阻碍是前一个模式遗留的系统代理、PAC 或 VPN 接管层，与目标模式发生冲突。

v0.1 将这些接管状态变成可见、可验证的切换事务：识别当前模式，选择目标模式，解释必须关闭与不会触碰的对象，经用户确认后切换并验证；失败时仅在安全条件下恢复原状态。

## 2. 产品边界

### 纳入 v0.1

- 用户登记并启用网络模式：直连、Clash 代理、Surge VPN、Palantir VPN。
- 识别系统代理、PAC、登记 VPN 服务、默认路由、DNS、`utun` 和必要的本地端口，作为模式判定与切换验证证据。
- 展示当前模式、目标模式、冲突项，以及本次切换将关闭、启动和不触碰的对象。
- 执行“预检 → 确认 → 切换 → 验证 → 条件化回退”的网络模式切换事务。
- 在切换过程中清理属于**当前已知模式**的系统代理/PAC 残留，防止它阻碍目标模式。
- 记录不含敏感信息的操作摘要和验证结果。

### 不纳入 v0.1

- 读取、保存或修改订阅链接、令牌、节点账号密码。
- 自动选择/测速第三方客户端内部节点。
- 自动修复第三方客户端内部配置，或根据日志推断其根因。
- 泛化的“一键网络修复”或独立的 DNS、默认路由、网络扩展清理功能。
- 删除 Clash/Surge/Palantir 应用、配置、网络扩展或 VPN 描述文件。
- 绕过系统权限、证书告警或第三方客户端的安全机制。

## 3. 模式与配置模型

模式是“流量接管方式”，不是对某个客户端内部状态的承诺。产品名仅是用户登记后的显示标签；所有实际操作均绑定稳定的系统服务 ID、已登记的代理地址/端口和已验证的 VPN 服务。

| 模式 | 预期接管状态 | 切入前必须消解的冲突 | v0.1 不触碰 |
|---|---|---|---|
| 直连 | 已登记服务的系统代理/PAC 关闭；已验证且属于当前模式的 VPN 已断开；默认路由回到物理网卡 | Clash 系统代理、已登记 VPN | 节点、订阅、DNS 配置 |
| Clash 代理 | Clash 本地端口监听；已登记服务的 HTTP/HTTPS/SOCKS 指向该端口 | 已登记 VPN、冲突代理/PAC | Clash 内部节点、规则、订阅 |
| Surge VPN | 已验证的 Surge 系统 VPN 服务已连接，并出现预期隧道/路由证据 | Clash 系统代理、Palantir VPN | Surge 内部配置、DNS 配置 |
| Palantir VPN | 已验证的 Palantir 系统 VPN 服务已连接，并出现预期隧道/路由证据 | Clash 系统代理、Surge VPN | Palantir 内部配置、DNS 配置 |
| 冲突 / 未知 | 多个接管层同时生效，或无法匹配任一已登记模式 | 不自动猜测或覆盖 | 一切未登记服务与配置 |

### 模式登记

每个模式配置只保存切换所需的最小元数据：模式 ID、显示名、目标网络服务 ID、系统代理地址/端口（如适用）、VPN 服务 ID（如适用）与“已验证可操作”状态。显示名称只用于界面确认，不能作为唯一操作目标。不得保存订阅 URL、令牌、节点地址、规则正文或完整诊断原始输出。

## 4. 技术架构

```text
SwiftUI MenuBarExtra
        |
   AppState / ViewModel
        |
  NetworkModeService
  ├── ModeProfileStore     已登记模式与能力状态
  ├── StateCollector       只读采集
  ├── ModeClassifier       当前模式、冲突与未知状态
  ├── TransitionPlanner    目标模式的变更预览与阻断条件
  ├── HealthVerifier       切换后结构与连通性验证
  ├── SnapshotStore        最小快照与条件化回退计划
  └── ModeTransaction      确认后执行、验证与回退
        |
 macOS 网络命令与 API
```

### 只读采集

优先使用稳定的系统命令与 API：

- `networksetup`：网络服务、HTTP/HTTPS/SOCKS/PAC 代理与 DNS 状态。
- `scutil --nc list`：已注册 VPN 的连接状态。
- `route -n get default`：默认路由及接管接口。
- `ifconfig -l`：虚拟网卡存在性（仅辅助证据）。
- 受限的本地端口探测：确认已配置的 Clash 端口是否监听。
- 短超时 HTTPS/DNS 探测：仅用于切换后健康验证，不作为第三方客户端故障归因。

采集器只返回结构化状态和脱敏错误类别；不保留完整命令输出。

### 写入与授权

切换网络模式属于敏感系统设置。界面必须先展示精确的操作预览，经用户确认后才通过受控的授权写入层执行。仅允许操作用户已登记的网络服务和已通过真实机验证的 VPN 服务；未验证模式只能显示状态，不能成为切换目标。

### 模式切换能力矩阵（M3 前置门槛）

切换不是“发现了就关掉”。每条路径均须在真实机验证授权、成功、拒绝、服务缺失与外部并发修改；未验证的目标模式在界面中置为不可切换。

| 切换能力 | 精确操作范围 | 预检与预览 | 验证与条件化回退 | v0.1 结论 |
|---|---|---|---|---|
| 切换至直连 | 已登记网络服务的 HTTP/HTTPS/SOCKS/PAC；以及已验证、属于当前模式的 VPN 服务 | 列出将关闭的每一项；不碰 DNS、客户端配置和未登记 VPN | 逐字段确认代理/PAC 已关闭、登记 VPN 已断开、路由证据符合预期；仅回退仍保持本事务写入值的字段 | 支持系统代理/PAC；VPN 部分依赖真实机验证 |
| 切换至 Clash 代理 | 已登记网络服务的 HTTP/HTTPS/SOCKS 指向已登记本地端口 | 先确认端口监听；列出将关闭的登记 VPN、PAC 与冲突代理 | 重新读取代理字段并确认端口可达；失败时恢复原代理/PAC 与已记录的可恢复状态 | 支持，不启动 Clash 或选择节点 |
| 切换至 Surge VPN | 已验证的 Surge 系统 VPN 服务；关闭已登记的 Clash 代理/PAC 与冲突 VPN | 必须证明该 VPN 服务可见、可操作；列出将断开与将连接的服务 | 确认目标服务连接及路由/连通性证据；失败时只恢复可安全恢复的系统代理/PAC 与 VPN 状态 | 仅在真实机 spike 通过后支持 |
| 切换至 Palantir VPN | 已验证的 Palantir 系统 VPN 服务；关闭已登记的 Clash 代理/PAC 与冲突 VPN | 同 Surge；不操作未登记服务 | 同 Surge | 仅在真实机 spike 通过后支持 |
| 处理残留代理 / PAC | 仅属于“正离开的已知模式”且阻碍目标模式的代理/PAC 字段 | 作为切换预览的一部分列出，不提供无上下文的一键清理 | 写后重新读取；若被 MDM/描述文件管理或外部改写，停止并说明阻断原因 | 支持，附属于切换事务 |

**事务保护规则**：一次事务只能变更矩阵中已验证的、同一切换路径所需字段。写入后必须重新读取并逐字段比对预期值；任一字段不一致即失败。回退不是无条件覆盖：只有字段仍保持本事务写入后的值才恢复快照；若检测到第三方客户端、系统设置或 MDM 的并发改动，则保留现状、展示差异并要求用户决定。

**真实机验证清单**：每条拟支持模式转换都需要覆盖正常授权、拒绝授权、目标服务缺失、网络服务切换、受 MDM/描述文件管理、第三方客户端在事务中修改配置，以及写入后 DNS/HTTPS 验证失败等场景。验证结果必须以脱敏结构化证据保存，不保存订阅 URL、令牌、节点地址或完整诊断输出。

## 5. 切换阻断与解释规则

| 状态 | 证据 | 界面结论与操作 |
|---|---|---|
| 可切换 | 当前状态唯一匹配已登记模式，目标模式能力已验证 | 展示目标切换预览并允许确认 |
| 当前模式残留 | 代理/PAC 匹配正离开的已登记模式，但本地端口或客户端接管证据缺失 | 在本次切换中列为“将关闭的残留设置” |
| 模式冲突 | 两个以上已登记接管层同时生效 | 展示冲突清单；只允许选择有已验证消解路径的目标模式 |
| 目标未就绪 | 目标 Clash 端口未监听，或登记 VPN 服务不可操作/未通过验证 | 禁止切换，说明目标模式尚未准备好 |
| 受管理或外部改动 | 配置由 MDM/描述文件接管，或事务期间值被外部更改 | 停止写入或回退，展示不可安全操作的具体字段 |
| 未知 | 证据无法匹配任一已登记模式 | 只展示状态与证据，不提供会覆盖配置的操作 |

## 6. 网络模式切换事务

每次切换固定走以下步骤：

1. **识别**：采集状态，匹配当前已登记模式，或标记冲突/未知。
2. **选择目标**：用户选择一个已验证可操作的模式；不从第三方应用内部推测节点或配置。
3. **预检**：生成 `NetworkSnapshot`，列出将关闭、启动和不触碰的对象；存在未知接管层、受管理字段或无验证能力时阻止。
4. **确认**：用户确认本次网络变更范围。
5. **执行**：先关闭当前模式的已登记接管层与冲突项，再启用目标模式的已验证接管层。
6. **验证**：检查目标模式的系统状态、必要端口/隧道路由，以及 DNS/HTTPS 连通性。
7. **交付**：成功则展示前后证据；失败则展示精确失败点并执行条件化回退。

## 7. 交付节奏

### M1：模式登记与只读识别

- 完成 `ModeProfile`、`NetworkSnapshot`、采集器与模式分类器。
- 菜单栏以“当前模式 + 可切换目标 + 冲突数量”作为主界面，而非以诊断页作为主入口。
- 用模拟样本覆盖直连、Clash、登记 VPN、冲突与未知状态。

### M2：切换预检与解释

- 完成 `TransitionPlanner`、目标模式选择和“将关闭 / 将启动 / 不触碰”预览。
- 诊断详情仅在无法切换或用户需要查看证据时展开。
- 完成模式能力状态、MDM/外部改动阻断和脱敏操作摘要。

### M3：确认式切换与回滚

- 完成授权执行、快照、字段级验证和条件化回退。
- 先落地“直连 ↔ Clash 系统代理”。
- Surge、Palantir 只有在系统 VPN 服务控制的真实机 spike 通过后，才按已验证能力加入切换目标；不通过则保持只读状态。

### M4：真实机验收与发布

- 对每一条已支持的模式转换逐项验收：成功、授权拒绝、目标缺失、冲突、外部并发修改与验证失败。
- 打包为本地 `.app`，不自动上传或发布。

## 8. v0.1 验收标准

- 用户可以一眼看到当前已登记模式、可安全切换的目标模式和阻断原因。
- 每次切换都明确展示“将关闭、将启动、不触碰”的精确范围；不包含节点、订阅、规则或 DNS 配置操作。
- `直连 ↔ Clash` 的每一次写入均先确认、后验证；失败时仅对未被外部修改的字段执行回退。
- Surge/Palantir 只在其登记 VPN 服务已经通过真实机控制验证后才允许切换；否则不显示为可执行承诺。
- 代理/PAC 残留只作为从一个已知模式切到另一个模式时的冲突项处理，不提供脱离切换语境的一键清理。
- 操作记录不含订阅 URL、令牌、节点凭据、规则正文与完整访问域名。
